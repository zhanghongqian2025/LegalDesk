# LegalDesk 单机法律 Agent 工作台重构清单

## 产品边界

LegalDesk 面向律师、公司法务和法律服务团队，是单机运行、可私有部署演进的专业工作台。案件是数据和 Agent 运行的强制边界；模型输出默认是待人工审核的草稿。系统不提供公共法律咨询，不自动发送、签署或提交法律文件，也不把模型回答表述为最终法律意见。

## 功能清单

### P0：可运行闭环

- **单机 Harness 基座**：以 DeepSeek Harness 的 Profile、Bundle、Session、Agent Loop 和 Web Surface 为运行基础，支持本地启动、流式输出、会话恢复和错误诊断。
- **案件空间**：创建、编辑、归档案件；每个案件对应独立受管工作区；拒绝非法案件标识、目录穿越和跨案件材料引用。
- **材料管理**：导入材料、记录类型和摘要、显式选择本次 Agent 输入；首期只向模型发送经过校验的文本快照，不把任意文件系统工具交给模型。
- **法律 Agent 预设**：材料整理、证据审阅、文书起草三个固定角色；角色分别拥有强制输出约束，不能退化为无边界通用助手。
- **运行控制**：运行前展示案件、角色、选材、模型提供方和联网状态；支持取消、失败恢复和状态查询。
- **权限策略**：默认只读、默认无模型工具、联网关闭、敏感动作必须审批；编程 Agent 预设、shell、文件写入、技能、自修改、子 Agent 和工作流默认不可用。
- **审计记录**：持久化角色、案件、材料清单、指令、Harness Session、事件、状态、错误和产物；模型可见内容必须能从日志重建。
- **产物审核**：产物状态为 `draft -> pending_review -> accepted | rejected`；保留引用和修改记录；只有人工可以确认接受。

### P1：专业工作台

- 案件导航、材料区、Agent 对话/轨迹区、产物审阅区组成的工作台界面。
- 文书模板、证据目录、争议焦点、时间线和待核验事项。
- 受控法规与案例数据源；数据源、查询词、结果和引用可审计，且每次联网都受策略控制。
- 本地备份、恢复、JSON/ZIP 合规导出、存储配额、日志脱敏和保留期限。
- 模型与密钥配置只保存凭据引用；运行前明确展示数据将发送到哪个提供方。

### P2：机构部署

- 本机多角色权限、机构策略包、模板包和审计导出。
- 可选机构内网模型、统一密钥托管、集中更新与运维基线。
- 团队协作和机构连接能力单独设计，不把单机数据模型直接扩成公共多租户 SaaS。

## 首阶段验收

- LegalDesk 以独立 Bundle 叠加在 DeepSeek Harness 上，不修改 Harness 核心。
- Bundle 与启动器最终 overlay 强制 `read-only + ask`，关闭 Harness 遥测、默认编程预设和全部模型工具；启动器校验最终配置，防止用户级 patch 降级策略。
- 三个法律 Agent 定义可校验，生成的运行指令包含案件标识、显式材料清单、角色约束和人工审核声明。
- 案件路径解析拒绝非法标识、绝对子路径和目录穿越。
- 相关单元测试通过，Bundle 可被 `npm pack --dry-run` 完整打包。
- SQLite 可持久化案件、材料、快照、运行、Session 关联、草稿和审核记录。
- Harness 页面侧栏出现“法律工作台”，可查看案件、导入并选择材料、创建快照和启动三个 Agent。
- 启动 Agent 后，Legal Run 页面显示真实 `HarnessSessionId`，完成输出进入待审核区。

## 首阶段非目标

- 不迁移旧 SQLite 数据；旧 Tauri/Pi 实现已删除，历史数据迁移需另行设计导入器。
- 不在第一阶段开放 shell、文件工具、联网检索或子 Agent。
- 首版只抽取 UTF-8 文本、Markdown、JSON 和 CSV；PDF、Office、图片仅受管保存并记录校验值，正文抽取/OCR 后续实现。
- 不承诺 DeepSeek Harness 开发预览版本之间的配置兼容性；每次升级必须做 Profile 配置和会话格式回归。
