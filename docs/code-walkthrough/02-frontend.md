# LegalDesk 前端代码走读

本文对应当前工作树中的 React/Tauri 前端。主覆盖范围是 `src/**/*.ts`、`src/**/*.tsx`、`src/**/*.css` 和入口 `index.html`；另补充说明被 TypeScript 直接导入的 `src/agents/registry.json`。行号以本文生成时的工作树为准。

## 1. 总体数据流与信任边界

```text
用户操作
  -> 页面/组件的 React 本地状态
  -> Zustand useAppStore 或 src/ai/piClient.ts
  -> Tauri invoke / event
  -> Rust command、SQLite、受管案件目录、Pi 子进程
  -> 返回值或 legaldesk-agent-event
  -> Zustand/组件状态更新
  -> React 重渲染
```

- React 负责交互、展示和输入的第一层约束；这些约束可以被绕过，不能视为安全控制。
- Zustand 保存当前窗口内共享的业务数据快照，没有自行持久化；真正的持久化发生在 Rust/SQLite。
- 所有 `invoke(...)` 都跨越 WebView 与 Rust 的 IPC 信任边界。路径、ID、文件大小、智能体权限和备份内容必须由 Rust 再次验证。
- Pi 的前端边界是“选择智能体、材料和任务，显示运行状态”；是否零工具、材料快照大小、进程参数和审计落库均由 Rust 强制。
- 模型输出只按“待复核草稿”展示，前端没有自动提交、自动覆盖业务数据或把结论标记为最终意见的入口。

## 10. 关键端到端流程

### 10.1 资料纳管

1. `App.tsx:56–77` 仅在本地队列暂存原文件路径。
2. `App.tsx:79–105` 先经 store 创建案件，再逐个调用 `importFileToCase`。
3. `store/index.ts:116–123` 通过 `import_file_to_case` 把案件 ID、源路径、类别交给 Rust。
4. Rust 应验证案件 ID、源文件、目标案件目录和冲突策略，复制成功后返回 `Document`。
5. Store 前插返回记录；`selectCase` 重新获取该案件详情。

### 10.2 智能体运行

1. `AgentPanel.tsx:44–52` 先在 UI 禁用明显不支持的文件类型。
2. `AgentPanel.tsx:177–232` 用户显式选择注册智能体、可生成快照的材料和任务要求。
3. `AgentPanel.tsx:115–137` 经 `piClient.startAgentRun` 提交 ID列表，不提交路径、系统提示或工具权限。
4. Rust 重新验证案件/材料归属，读取受管文本并执行大小/编码限制，以零工具 RPC方式启动固定版本 Pi。
5. `piClient.ts:33–37` 接收全局 Tauri 事件；`AgentPanel.tsx:62–105` 按 run ID隔离并拼接 text delta。
6. 终态重新读取数据库运行记录；成功后读取 artifact，UI 标为待人工复核。

### 10.3 文书模板

1. 内置模板来自 `data/templates.ts`，用户模板经 store 从 SQLite 读取。
2. `DocumentWizard.tsx:24–36` 建立变量输入字典。
3. `DocumentWizard.tsx:38–47` 纯字符串替换并保留未填占位符。
4. `DocumentWizard.tsx:49–58` 经 `save_legal_document` 落库，Store 用后端返回版本更新列表。
5. 模板和正文从不以 HTML注入页面；React 进行文本转义。

### 10.4 备份恢复

1. `App.tsx:112–128` 只将 Rust 导出的 JSON下载为本地文件。
2. `App.tsx:130–150` 用户确认后读取一个 JSON文本并交给 `import_app_data`。
3. `accept=.json` 与 confirm 都只是 UX；Rust 必须验证 schema、ID/外键、路径重写并在事务内覆盖。
4. 成功后前端刷新案件/模板并清空案件选择，避免继续显示导入前的陈旧详情。

## 11. 当前前端边界与已知改进点

- **安全强制位置**：前端扩展名、disabled、注册表和确认框均可被绕过；受管路径、文件快照、Pi 零工具、固定版本、ID/外键和备份事务必须由 Rust保证。
- **模型输出**：当前始终以 `<pre>` 文本输出并标记待复核，没有 HTML执行面，也没有自动写回案件事实或文书。
- **错误一致性**：智能体和资料入口有可见错误；多数 Zustand fetch 只写 console，案件/模板 CRUD 也缺统一 loading/error通道。
- **可访问性**：新智能体/资料入口组件具有 fieldset、legend、focus-visible、状态文字和 reduced motion；旧案件、模板与向导仍存在无 aria-label 图标按钮、无 htmlFor label、可点击 div 和不完整 dialog语义。
- **并发与陈旧响应**：`selectCase` 的三次详情请求和部分页面初始请求没有取消机制；快速切换案件时宜用请求 token或检查返回案件 ID。
- **文案一致性**：案件详情仍称文件“仅保存引用”，而当前 `import_file_to_case` 是复制到受管目录，应统一为纳管语义。
- **模板替换**：自定义变量在进入 `RegExp` 前未转义，变量名含正则元字符时可能替换错误；这不是代码执行，但会破坏文书正确性。
