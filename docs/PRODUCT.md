# LegalDesk 产品说明

## 一句话定义

LegalDesk 是以案件和卷宗为边界、基于 DeepSeek Harness 构建的单机法律 Agent 工作台。

## 服务对象

核心用户是律师、企业法务和法律服务团队。产品帮助专业人员接收和整理材料、形成证据审阅底稿、起草文书并保留完整审核轨迹，不面向公众提供自动法律咨询。

## 核心工作流

```text
创建案件 → 导入材料 → 明确选材 → 选择法律 Agent
        → Harness 受控运行 → 生成待审核草稿 → 人工修改/接受/驳回
```

## 功能定义

### 案件工作区

- 案件信息、材料、运行、会话和产物统一归档。
- 当前案件始终可见，不允许跨案件隐式检索。
- 材料导入不等于内容已核验；来源、哈希和提取状态需要记录。

### 材料整理 Agent

- 建议材料分类和目录。
- 发现重复、缺失、日期冲突和待确认信息。
- 区分事实、推断和待核验项，不改动原始材料。

### 证据审阅 Agent

- 从真实性、合法性、关联性提供核验线索。
- 列出证明目的、争议点、补证方向和材料来源。
- 不作最终事实或证据认定。

### 文书起草 Agent

- 根据案件信息、明确选材和任务生成结构化草稿。
- 缺失信息使用待确认占位符。
- 不虚构事实、法条、案例、主体、金额或日期。

### 人工审核

- 产物默认进入待审核状态。
- 修改、接受和驳回均记录操作者、时间和理由。
- 系统不自动导出、签署、发送或提交法律文件。

## 技术产品原则

- DeepSeek Harness 是唯一 Agent 生命周期、会话、模型路由和前端运行基座。
- LegalDesk 通过 Host/Client 插件增加案件领域，不维护 Harness 核心分叉。
- 本地优先不等于推理离线；模型提供方和数据范围必须在运行前透明。
- 风险、来源和待核验信息比“生成成功”更醒目。
- UI 保持专业、克制和高信息密度，并满足键盘、焦点、对比度和减少动态效果要求。

## 成功指标

- 从选材到首份可审核产物的时间。
- 关键内容可追溯到选定材料的比例。
- 人工发现的虚构事实和错误引用数量。
- 越权材料与工具调用的拒绝率。
- 产物接受、修改和驳回的分布。
