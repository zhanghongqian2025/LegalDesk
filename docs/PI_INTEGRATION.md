# Pi 集成与升级策略

## 决策

LegalDesk 使用 [earendil-works/pi](https://github.com/earendil-works/pi) 提供智能体运行能力，当前兼容包为：

```text
@earendil-works/pi-coding-agent@0.84.1
```

采用 **核心零 fork + LegalDesk 薄适配层**。法律角色、提示约束、材料选择、权限、审计和人工审核属于 LegalDesk；会话、模型调用和允许的工具执行交由上游 Pi。除非出现上游无法接受且无法通过扩展或适配解决的阻断问题，不维护 Pi 分叉。

## 为什么先用 RPC

Pi CLI 的 RPC 模式可通过 JSONL 控制会话并接收事件，适合由 Tauri/Rust 管理独立子进程：

- 与前端隔离，模型密钥不需要进入浏览器状态；
- 易于终止、超时和记录退出状态；
- 上游升级影响集中在一个协议适配器内；
- 不要求把 Node 运行时逻辑嵌入 Rust 进程。

SDK 仍是保留路径。当需要进程内创建 `AgentSession`、更细粒度会话编排或自定义宿主 UI 时，可在不改变产品层接口的前提下切换或补充 SDK 适配。

## 安装与发现

开发版不自动安装 Pi。用户必须显式安装固定版本，并对所选模型提供方的数据处理规则负责。

```bash
npm install --global @earendil-works/pi-coding-agent@0.84.1 --ignore-scripts
pi --version
```

如果组织策略禁止全局 npm 包，可由管理员提供审核过的 `pi` 可执行文件，并通过 LegalDesk 支持的显式路径配置发现。无论采用哪种方式，运行前都必须检查版本；未安装或版本不匹配时，智能体功能保持不可用，但案件与卷宗功能仍可使用。

安装命令只是开发期参考。组织部署前应验证上游发布物、锁文件、许可证和依赖来源，并通过内部软件分发流程交付。

## 运行参数基线

首期适配器应等价于以下安全意图，实际实现使用参数数组而非 shell 字符串：

```text
pi
--mode rpc
--no-tools
--no-approve
--no-extensions
--no-skills
--no-prompt-templates
--no-themes
--no-context-files
--session-dir <current-case>/.legaldesk/sessions
--system-prompt <selected-agent-system-prompt>
```

工作目录必须是当前案件的受管目录。`<current-case>`、会话名称和提示内容均不能未经校验拼接到 shell 命令。启动前由 Rust 校验材料归属、canonical path、普通文件、类型和大小，并把内容快照作为不可信数据写入提示；Pi 本身不获得文件工具。

## 允许与禁止

默认允许：

- 由 LegalDesk 读取当前案件中用户明确选择的受管 UTF-8 文本（`txt/md/csv/json/xml/html/log`）；
- 将单文件不超过 256 KiB、单次合计不超过 1 MiB 的内容快照交给 Pi；
- 向 LegalDesk 返回文本事件和待审核产物；
- 把会话与运行审计写入 LegalDesk 管理的数据结构。

默认禁止：

- shell/命令执行；
- 创建、修改、移动或删除原始案件文件；
- 读取其他案件、用户主目录或任意绝对路径；
- 自动加载第三方扩展、技能或上下文文件；
- 自动联网检索、发送邮件、提交文件或调用外部业务系统；
- 直接处理 PDF、Office 或图片二进制；这些格式必须等待后续受控提取管线；
- 在用户不知情时安装或升级 Pi。

## 提示注入与产物可信度

案件材料本身可能包含对模型的恶意指令。适配层与系统提示必须把材料视为待分析数据，而非可信指令来源。即使工具调用没有越权，产物仍可能包含错误事实、虚构法条或不完整分析，因此：

- 产物必须区分材料原文、推断和待核验项；
- 关键结论应尽量附材料来源；
- 产物默认进入 `pending` 人工审核状态；
- 不允许模型直接改变案件事实字段或产生外部法律行为。

## 模型与数据流

Pi 可以连接不同模型提供方。本地保存案件不代表推理必然在本地完成。LegalDesk 在运行前至少应显示：

- 当前模型或提供方；
- 将发送的案件与材料范围；
- 是否需要联网；
- 组织数据策略或保留规则的入口。

处理保密、特权或个人敏感材料前，用户和部署机构应确认模型提供方、地域、留存和训练政策满足适用要求。优先使用机构批准的私有端点或本地模型。

## 失败处理

| 情况 | 行为 |
|---|---|
| 找不到 Pi | 禁用运行并给出显式安装说明 |
| 版本不是 `0.84.1` | 拒绝运行，提示安装兼容版本 |
| 文件不属于当前案件 | 拒绝运行并记录安全错误 |
| RPC 输出无效 | 结束运行，保存原始错误摘要，避免把未知事件当产物 |
| 进程异常退出 | 标记失败，释放句柄，不将部分输出标记为已审核 |
| 用户取消 | 请求中止，最终状态标记取消，保留已有审计 |
| 运行超过 10 分钟 | 终止子进程并标记失败，不保存部分输出为草稿 |

错误日志不得无差别记录案件全文、模型密钥或完整敏感提示。

## 升级清单

Pi 版本升级需要独立变更并完成：

1. 核实仓库、包名、版本和 MIT 许可仍然一致。
2. 阅读上游变更，特别关注 RPC 事件、命令参数、工具默认值和扩展加载行为。
3. 运行版本检查、三类智能体端到端测试、取消/崩溃测试和路径越权测试。
4. 检查模型提供方配置与密钥处理没有迁移到前端。
5. 更新本文件、第三方通知和精确版本常量。
6. 经代码审阅后再发布；禁止自动跟随 `latest`。
